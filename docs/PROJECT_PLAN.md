# 完整项目推进计划

## 产品定位

先服务家里一年级、三年级两个孩子，做“能听懂、能自己做出来”的数学辅导。首要指标是讲解后的独立解题表现，而不是生成了多少视频。

视频呈现：温暖浅色教学板书、成人普通话教师配音、逐步图形演示。先将每个步骤讲清楚，再考虑把已设计的两姐妹和墨团加入片头、提问与鼓励环节；角色形象和声音需要另行锁定，当前项目未包含这些角色素材。

## 学习体验

家长拍题或输入题目 → 确认识别结果 → 孩子先尝试 → 必要时给一级提示 → 再给图解 → 仍不懂才看完整讲题视频 → 做一题不同数字的迁移题 → 隔天与稍后复习。

当前MVP已实现文字/题图输入接口、讲解确认、视频、一道迁移题及记录；尚未实现独立OCR确认页、分级提示状态与动态换题。

## 阶段与验收

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| 0：本次交付 | 本机源码、示例视频、分镜协议、模型/TTS/DeepTutor适配、练习记录 | 带配音MP4可播放；示例计算正确；档案记录分离；失败可见 |
| 1：目标机接通 | Mac安装、选定模型和配音、DeepTutor独立目录与教材库 | 真实题目经资料检索→讲解稿→视频→练习全程跑通；重启不丢记录 |
| 2：教学验证 | 平均分、加减进退位、乘法、周长面积的参数化模板 | 每类有人工核对题集；单位和数值校验；看不清题目时主动要求补充 |
| 3：家庭可持续使用 | 错因标签、每次不同迁移题、间隔复习、家长反馈 | 记录独立作答；多日跨题验证；可追溯每个复习建议的证据 |
| 4：对外产品 | 手机拍题、独立账号、队列、对象存储、成本与清理规则 | 用户间数据权限测试通过；失败重试和成本上限可控；手机端实测 |

排期取决于模型选择、目标机权限和题目测试反馈，不在尚未联调时承诺固定完成日期。

## 第一批测试材料

每个年级先各准备10道题，覆盖清楚印刷题、带图题、常见错误与条件不足题。先只取家庭使用所需内容，不需要一次导入所有教材。

建议记录表：题目ID、孩子的首次答案、讲解是否正确、哪个步骤没听懂、讲解后迁移题是否独立做对、两三天后换题是否仍会做。

## 模型和成本

- 输入题图：选择支持视觉输入的模型，或以后增加独立OCR。
- 解题和分镜：先用同一服务商的兼容接口；接DeepTutor时独立管理其配置。
- 配音：第一轮Edge验证；家庭长期使用可选Mac系统声音或稳定的商业TTS。
- 渲染：CPU上的固定模板+FFmpeg；复杂几何后续用Manim，讲故事类场景后续可用HyperFrames。

成本按真实调用统计：解题/检索调用 + 分镜调用 + TTS字数 + CPU渲染时间 + 视频存储。当前未接入账单API，不应给出“一个订阅无限生成”的承诺。

## Java开发者的演进路径

先保留Python MVP验证教学效果。如果要扩展为多人产品，再建立Spring Boot业务层，负责家庭、成员、题目、学习状态和任务管理；Python专心提供配音与渲染Worker。两层通过版本化JSON/任务消息通信。不要在教学方案尚未验证前迁移所有代码。

## 下一步需要落定的配置

目标运行位置（先默认Mac本机）、准确的解题/视觉模型ID与本机密钥来源、最终普通话声音、少量教材和测试题。密钥在目标机配置，不需要发到聊天里。
